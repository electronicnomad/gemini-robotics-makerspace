# 라인 센서 피드백 배선 (로보로보 보드 → Pi) 설계

작성일: 2026-07-13 (Claude Code 세션 답변 정리)

배경: 테이블 경계는 검은색 무반사 마커(현재 폭 5cm)를 바닥 센서로 읽어 로보로보 보드가
자체 후진 반사를 수행하는 구조. 속도(약 260mm/s) 대비 감지 시간 예산이 짧아 일정 확률로
경계를 넘는 문제가 있고, 오도메트리는 이를 보조하는 백스톱 역할. 이 문서는 보드의 라인
감지 신호를 Pi로 전달하는 배선 1가닥의 설계를 정리한다.

## 개념 — 한 가닥 배선이 주는 두 가지 효용

현재 신호는 Pi → 보드 단방향. 보드가 라인을 밟고 스스로 후진해도 Pi는 모른 채 전진
명령을 유지한다(서로 충돌). 보드의 "라인 감지" 신호를 Pi로 돌려주면:

```
[라인 센서] → [로보로보 보드: 회피 반사 + 출력포트 ON] ──(전선 1가닥)──> [Pi GPIO 입력]
                                                                    │
                                              1) 협조: Pi 명령 즉시 양보 (반사가 온전히 동작)
                                              2) 앵커: "지금 경계선 위" = 절대 위치 → 오도메트리 보정
```

## 1단계: 하드웨어 배선

1. 로보로보 쪽: 여유 출력 포트 하나 지정. 출력 전압 확인 필수 — **5V 출력이면 Pi에
   직결 금지**(Pi GPIO는 3.3V 최대). 저항 2개 분압(예: 직렬 10kΩ, GND로 15kΩ → 5V가
   3V로)이면 충분. 3.3V 출력이면 직결 가능.
2. Pi 쪽: **BCM 24**(물리 핀 18) 입력 권장 — 현재 출력 4개(BCM 17/27/22/23)와 안 겹치고
   헤더에서 가까움. 내부 풀다운 사용.
3. GND 공유: 기존 오픈드레인 제어가 동작 중이므로 이미 공유되어 있을 것 — 확인만.
4. 고장 모드가 안전함: 선이 끊기면 신호 없음 = 현재와 동일 (악화 없음).

## 2단계: 로보로보 프로그램(.rpj) 수정

기존 black-line if-else 블록에 한 줄 추가:

- 라인 감지 → (기존) 후진 기동 + (추가) 출력포트 ON
- 회피 기동 종료 → 출력포트 OFF

펄스가 아니라 **회피 지속시간 동안 레벨 유지** 방식 권장 — Pi가 놓칠 일이 없고,
"지금 보드가 반사 동작 중"이라는 상태 신호로도 쓰인다.

## 3단계: Pi 소프트웨어

수신: `GPIO.add_event_detect(24, RISING)` 인터럽트로 이벤트 시각을 정확히 기록(1ms 미만
지연), 실제 처리는 기존 30fps 비전 루프에서 수행.

### (a) 협조 양보 — 신호가 HIGH인 동안

- `robot.abort_event.set()` → 진행 중인 음성 버스트/기쁨 댄스 즉시 중단
  (안전과 동급 취급, 기존 우선순위 체계에 그대로 편입)
- `robot.stop()` → Pi의 모든 명령 핀이 High-Z로 풀려 보드의 후진 반사가 방해 없이 동작
- 신호가 내려간 뒤에도 짧은 홀드(약 1.5초)로 자율주행이 곧바로 다시 경계로 밀고
  나가지 않게 하고, 재개 시 안쪽으로 방향을 트는 행동 추가 가능

### (b) 오도메트리 앵커 — 이벤트 순간

- "센서가 라인 위" = 위치가 경계 링 위 어딘가라는 절대 정보.
- 어느 변인지 추정: 현재 추정 위치·헤딩으로 가장 그럴듯한 변 선택(헤딩이 향하는 변).
  그 축 좌표를 라인 중심 좌표로 스냅하고, 센서가 차체 중심에서 앞으로 d mm 떨어져
  있으면 보정: `위치 = 라인좌표 - d x 헤딩벡터`
- `position_uncertainty`를 잔여 오차(약 30mm: 라인 폭 절반 + 판정 오차)로 리셋 →
  경계에 닿을 때마다 오도메트리가 자가 보정. re-home 요청 빈도 급감.
- 코너 근처(두 변이 모두 후보)면 스냅 보류, 불확실성만 낮추는 보수적 처리.
- 한계: 라인은 위치 1축만 알려주므로 헤딩 드리프트는 남음 (헤딩까지 잡으려면 IMU 필요).

### 워치독

신호가 5초 이상 HIGH 고착이면(배선/프로그램 오류) 경고 후 무시 — 영구 양보 방지.

## 기대 효과 정리

| 문제 | 개선 |
|---|---|
| 보드 후진 vs Pi 전진 충돌 | 신호 동안 Pi 완전 양보 → 반사 성공률 상승 |
| 오도메트리 드리프트 누적 → 마비/re-home | 경계 접촉마다 위치·불확실성 리셋 → 세션 내내 유지 가능 |
| Pi가 경계 사건을 모름 | 대시보드 표시·감속 주의구역 재보정 등 활용 가능 |

## 구현에 필요한 정보 4가지

1. 로보로보 여유 출력 포트 번호와 출력 전압 (5V / 3.3V)
2. Pi GPIO — BCM 24 사용 가능 여부 (다른 핀 원하면 지정)
3. 라인 중심의 좌표: 테이블 가장자리에서 라인 중심까지 안쪽으로 몇 mm인지
   (앵커 스냅 좌표 계산용)
4. 라인 센서의 장착 위치: 차체 중심 기준 전방으로 몇 mm인지

참고: 배선 전이라도 Pi 쪽 코드를 먼저 구현해 둘 수 있음 (신호가 없으면 아무 동작도
하지 않으므로 무해). 배선 후 바로 테스트 가능한 순서.
